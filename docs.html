什么是 Demora

Demora（迪莫拉）是一款面向产品经理的 AI 辅助工具，核心理念很简单： 把模糊需求变成可点击的 Demo，让所有人围着同一个东西讨论。

传统的工作方式是：PM 先写 PRD 文档，再画原型图，再评审，再修改。Demora 把这个流程反过来—— 先出 Demo，再补文档。因为可点击的界面比静态文档更容易理解，也更不容易产生误解。

Demora 为产品经理设计了渐进式三阶段工作法：从想清楚需求，到做精致 Demo，再到改到位交付。每个阶段都有明确的输入和输出，AI 作为助手全程陪伴，帮 PM 发现遗漏、补全细节、把控质量。

ℹ
Demora 的定位：PM 是系统的第一用户，不是开发、不是测试。AI 助手从 PM 的视角理解需求，生成 Demo 和文档，帮助 PM 与用户、开发、测试在同一页面上达成共识。

三阶段工作流

Demora 的渐进式工作流分为三个阶段。每个阶段有明确的目标和产出物，阶段之间有严格的保护机制，确保需求不会在没有意识到的情况下被篡改。

PHASE 1 想清楚 — 需求对话与功能验证

这是需求的"探索期"。你（PM）把用户口述的需求、会议纪要、表格截图等任何资料告诉 AI 助手，AI 帮你结构化理解，主动发现遗漏和矛盾，并追问澄清。

输入需求资料（口述、截图、文档片段均可）
AI 结构化理解，提取页面、实体、字段、流程
AI 主动追问，补全遗漏信息
生成可交互 Demo（功能完整，实现朴素）
AI 输出需求完成度与缺失项清单
你拿着 Demo 给用户确认，收集反馈，循环迭代
用户确认"功能对了" → 说"锁定需求"进入 Phase 2
PHASE 2 做精致 — 完善与文档生成

需求锁定后，AI 在 Phase 1 Demo 的基础上注入式增强，不丢弃重写。补全 Mock 数据、表单校验、权限控制、错误处理，同时生成完整的配套文档。

需求模型自动锁定（只读），Demo 进入可修改状态
补全 Mock 数据（覆盖正常态、边界态、异常态）
补全表单校验、状态流转、权限控制、错误处理
完善三层标注（页面级 / 区域级 / 元件级）
自动生成 PRD + Spec + Test 配套文档
质量校验（Demo 与需求模型一致性检查）
说"打包交付"生成最终交付包
PHASE 3 改到位 — 评审修订

你拿着 Demo 和文档给开发、测试评审，收集修改意见。AI 会判断每个修改是"实现级微调"还是"需求级变更"，走不同的处理路径。

PM/开发/测试评审，收集修改意见
AI 判断修改类型并给出判定依据
实现级微调 → 直接修改 Demo，同步更新文档
需求级变更 → 解锁模型，回到 Phase 1 重新确认
修改最小化：精准改动、影响范围声明、diff 展示
确认无误后说"确认定稿"进入终态
⚠
关键设计：Demo 只有一份，从 Phase 1 持续演进。不存在"预览版"和"完整版"两套代码。Phase 1 的 Demo 就是最终 Demo 的起点，后续阶段在其基础上层层完善。

如何开始使用

Demora 的 AI 助手以 Skill（技能包）的形式集成在 AI 工具中。你不需要安装任何软件，也不需要懂编程——只需要像跟同事聊天一样，用自然语言与 AI 助手对话。

第一步：描述你的需求

用任何你喜欢的方式告诉 AI 助手你在做什么产品。可以是一段口述记录、一份会议纪要、一张表格截图，甚至是手绘的草图照片。越详细越好，但不用追求完美——AI 会主动追问补全。

第二步：跟着 AI 的节奏走

AI 助手会在每轮对话结尾告诉你当前处于哪个阶段、需求完成度是多少、下一步建议做什么。你只需要按它的提示回答追问、确认信息、预览 Demo。

第三步：拿 Demo 去确认

Phase 1 生成的 Demo 是可点击的网页原型。双击本地启动文件即可在浏览器中打开。把它展示给用户、开发、测试，收集反馈，然后回来告诉 AI 助手需要修改什么。

第四步：锁定 → 完善 → 交付

当用户确认"功能对了"，你说"锁定需求"，AI 进入 Phase 2 自动补全细节并生成文档。最后说"打包交付"即可获得完整的交付包（Demo + 文档 + 追溯矩阵）。

ℹ
Skill 会持续升级：Demora 的 AI 助手 Skill 会不断迭代优化。每次升级后，你只需使用最新版本的 Skill，即可享受改进的追问策略、更完善的 Demo 生成和更丰富的文档模板。你无需关心技术细节，只需像使用新版本的办公软件一样使用最新 Skill 即可。

常用指令

以下是你与 AI 助手对话时常用的关键词。用自然语言即可，不需要记忆精确格式。AI 助手会理解你的意图并给出对应的结构化回应。

"锁定需求"
Phase 1 中，当你确认需求已经足够清晰、用户也认可功能时，说"锁定需求"。AI 会展示锁定清单，确认后需求模型变为只读，进入 Phase 2。
"解锁"
Phase 2 或 Phase 3 中，如果发现需要修改需求模型（比如新增实体、新增页面、修改字段），说"解锁"。AI 会要求你提供解锁原因，确认后需求模型恢复可编辑，回到 Phase 1。
"打包交付"
Phase 2 完成后，说"打包交付"。AI 会展示交付物清单（Demo + 文档 + 追溯矩阵），确认后打包为最终交付包，可直接交给开发团队。
"生成文档"
Phase 2 中，如果你想单独触发文档生成，可以说"生成文档"。AI 会基于锁定的需求模型，自动生成 PRD、Spec、Test 三层文档。
"完善 Demo"
Phase 2 中，如果你想单独触发 Demo 完善，可以说"完善 Demo"。AI 会补全 Mock 数据、校验规则、权限控制、错误处理等细节。
"确认定稿"
Phase 3 末尾，当所有评审意见都处理完毕后，说"确认定稿"。AI 会做最终检查，确认后 Demo 和文档进入终态，不可再修改。
✌
提示：你不需要背诵这些指令。用自然语言表达同样的意思即可，比如"我觉得可以了，锁定吧""帮我生成文档""这些改完了，可以定稿了"——AI 助手都能理解。

常见问题

Q: 我需要会编程才能使用 Demora 吗？
完全不需要。Demora 面向产品经理设计，所有交互都是自然语言对话。你不需要懂代码、不需要配置环境、不需要管理文件——像跟同事聊天一样使用即可。
Q: Demora 生成的 Demo 可以直接上线吗？
不能。Demo 是可交互原型，用于需求确认和沟通对齐，不是生产代码。它使用模拟数据，界面是真实可点的，但后台逻辑是简化的。开发团队需要基于 Demo 和配套文档重新开发。
Q: 如果用户看了 Demo 后说"这个不对"，怎么办？
这正是 Demora 设计的工作流。你带着用户的反馈回来，告诉 AI 助手需要修改什么。如果在 Phase 1，直接修改即可；如果在 Phase 2/3，AI 会判断修改类型——实现级微调直接改，需求级变更需要解锁后回到 Phase 1。
Q: Demora 适用于什么类型的产品？
Demora 是系统无关的，适用于任何管理后台类产品：CRM、ERP、OA、SaaS 后台、运营管理系统等。它不绑定特定技术栈或业务领域，实体、字段、页面都从你的需求输入中动态提取。
Q: 生成的文档包含哪些内容？
配套文档分为三层：PRD 产品需求文档（14 份，覆盖总览、背景、用户、流程、页面、字段、权限等）、Spec 技术规格文档（7 份，覆盖技术栈、架构、交互、状态、路由、接口、异常）、Test 测试建议文档（3 份，覆盖验收标准、测试用例、权限矩阵）。所有文档从锁定的需求模型自动生成，确保与 Demo 一致。
Q: 为什么 AI 有时会问我"这个字段必填吗？"
这是 Demora 的主动追问机制。当 AI 从你的输入中无法确认某个信息时，它会标记为"待确认"并直接问你，而不是自己猜测。这是为了保证生成的 Demo 和文档准确反映你的真实需求，避免"AI 瞎猜"导致的偏差。
Q: 多个项目可以用同一个 Skill 吗？
可以。Skill 是通用的需求澄清助手，不绑定特定项目。每次使用时，只需向 AI 描述新的项目需求即可。AI 会为每个项目独立维护需求模型、对话历史和交付物，项目之间互不干扰。
