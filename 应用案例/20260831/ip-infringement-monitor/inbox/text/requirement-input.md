# 线上AI智能侵权监测与快速维权取证系统 — 需求详版

> 来源：inbox/text/requirement-scenario-brief.md（PM 原始输入）
> 本文档由 AI 基于 PM 简述 + 需求澄清扩展，作为 Phase 1 需求模型填充与 Phase 2 原型设计的输入。

## 1. 业务背景

线上电商（淘宝/京东/拼多多）、1688 批发、跨境平台（Amazon/eBay/Shopee/Lazada/Temu）及短视频、独立站、展会渠道的专利仿冒商品泛滥。品牌方传统维权依赖人工检索截图，存在三个硬伤：一是人工全网检索周期长（单轮 3-7 天），侵权链接常在取证前已下架或改价；二是截图类证据易被质疑篡改，司法采信度低；三是区块链存证已成为司法采信的硬性标准，但缺乏从"监测命中"到"存证取证"再到"分级处置"的一体化数字工具，快速维权中心存在显著工具缺口。

本系统的价值主张：以 AI 爬虫多渠道实时监测为入口，把"发现侵权"到"完成区块链存证"压缩到 24 小时内，并通过分级处置与跨境规则模板，让维权动作可跟踪、效果可量化。

## 2. 用户角色

- **品牌方IPR**：权利人与专利资产的归口人。发起监测任务、确认线索真实性、发起立案与处置审批、跟进维权进度与效果报表。关注"我的专利被谁侵权、处置到哪一步"。
- **维权律师**：重度侵权案件的处理人。接收自动升级的高风险案件，输出诉讼/无效方案，出具律师函。关注"证据链是否完整、时效是否过期、适用法域规则"。
- **监测分析师**：执行层。配置爬虫监测任务与渠道策略，复核机器命中结果，执行存证取证操作并生成标准化取证报告。关注"待办队列、24 小时存证时效倒计时、重复线索去重"。

## 3. 核心功能

- **多渠道全网侵权监测**：电商/独立站/短视频/展会四类渠道的爬虫监测任务管理，命中结果生成侵权线索，含相似度评分与风险分级（高/中/低）。
- **区块链存证取证**：对命中线索一键发起区块链存证，生成存证哈希与时间戳，支持录屏/页面快照/公证多种取证方式，输出标准化取证报告（PDF）。
- **维权分级处置**：按侵权严重程度与证据完备度选择处置策略——平台投诉函、律师函、专利无效检索、诉讼前置，并流转至对应责任角色。
- **跨境维权专项**：维护欧美/东南亚各国各平台的投诉规则模板（响应时效、材料清单、受理渠道），跨境案件必须绑定当地规则模板才能提交。
- **案件全流程跟踪与效果统计**：案件状态机（待处置→处置中→平台受理→已下架/已结案/已驳回）全程留痕，按渠道/地区/专利维度统计下架率、平均处置周期、维权收益。

## 5. 业务规则

- **24 小时存证时效**：监测命中后必须在 24 小时内完成区块链存证，超时后线索状态置为"已失效"，证据不可再用于司法举证；工作台与线索清单对剩余时长分级预警（>12h 正常 / 4-12h 警告 / <4h 危险）。
- **不可重复立案**：同一卖家 + 同一专利只可存在一条在办案件；发起立案时若命中重复组合，阻断提交并跳转到已有案件。
- **高风险自动升级**：风险等级为"高"或侵权规模达到批量阈值（同卖家同专利命中商品数 ≥ 5）的线索，立案时处置策略自动预选"诉讼前置"并指派维权律师，品牌方IPR 可改派但需填写理由。
- **跨境规则绑定**：渠道归属海外（Amazon/eBay/Shopee/Lazada/Temu 等）的案件，必须绑定对应国家/地区的投诉规则模板后方可提交处置；未绑定时提交按钮阻断并提示缺失项。
- **状态流转约束**：线索状态 待存证 → 已存证 → 已立案 → 结案；已失效与已忽略为终态，不可逆回。案件状态 待处置 → 处置中 → 平台受理 → 已结案/已驳回，驳回可退回处置中。
- **权限边界**：监测分析师可执行监测与存证操作，无立案与处置审批权；品牌方IPR 拥有立案、处置策略确认与结案权；维权律师拥有重度案件处置方案与律师函出具权，不可修改监测任务配置。

## 6. 验收标准

- 页面结构与标注：6 个页面的 `data-page-id` 与导航项一一对应，每页 L2 区域覆盖 hero/筛选/列表/统计/操作区，L3 标注覆盖按钮、输入框、下拉选择、链接等可交互元件类型（check-structure S-1~S-14 / run-audit D5、D8、D10 可验证）。
- 交互实质性：筛选与搜索必须真实过滤列表行并同步更新计数文本；一键存证必须产生业务状态变化（线索状态变更为已存证、生成存证哈希与时间戳、倒计时停止）；24 小时超时线索自动置为已失效（run-audit D6 业务状态签名、筛选往返一致性探针可验证）。
- 表单与校验：立案弹窗对重复卖家+专利组合阻断提交并提示；跨境案件未绑定规则模板时阻断提交；必填项缺失时给出错误提示并阻断（pre-audit-check P036/P038/P039 静态检测 + D6 运行时可验证）。
- 弹窗闭环：存证、立案、规则绑定等弹窗可正常开启与关闭（run-audit D3 可验证）。
- 数据质量：每个业务实体 mock 数据不少于 10 条，覆盖正常/边界/异常态（check-business-fill 可验证）。
- 视觉与运行时：无 console error 与 404 资源，无横向溢出，导航切换后公共区域保持完整（run-audit D0、D7、D10 可验证）。
