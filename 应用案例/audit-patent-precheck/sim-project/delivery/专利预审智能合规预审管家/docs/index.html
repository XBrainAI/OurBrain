业务背景

本系统面向 PATENT 领域的核心业务场景。当前专利预审智能合规预审管家旨在通过数字化手段整合预审案件等业务模块，实现数据集中管理、流程标准化与跨角色协作提效。项目定位为：专利预审案件全流程管理与智能预检平台。

核心痛点

  1. 痛点一：预审案件管理缺乏统一系统支撑，数据分散、流程不规范、跨角色协作效率低

解决方案

专利预审案件全流程管理与智能预检平台。通过构建PATENT一体化管理平台，实现以下能力：

  • 数据集中化：将预审案件数据统一存储与管理，消除数据孤岛
  • 流程标准化：将核心业务流程（录入、审批、状态流转）固化到系统，减少人为差错
  • 权限精细化：基于 RBAC 模型实现角色-实体-操作三级权限控制，保障数据安全
  • 协作在线化：多角色在线协同，审批流自动流转，提升跨部门协作效率
  • 决策数据化：提供实时数据看板与报表，支撑管理决策

专利预审智能合规预审管家需求

背景

全国 77 家知识产权保护中心全覆盖广州产业园区，预审通道可将发明专利授权周期压缩至 3 个月；国知局严控预审准入，自动筛查非正常、低质量申请成为企业与代理机构刚需。

核心功能

  • 预审准入智能预检引擎（主体备案/技术领域/同日重复校验）
  • 非正常专利全维度筛查（研发证明/技术逻辑/权利要求/附图/发明人）
  • 预审文本智能修正与标准化模板适配
  • 预审案件全流程台账与时限提醒
  • 工具预检 + 人工复核一体化

用户角色

  • 代理师：提交预审案件，跟进整改
  • 预审员：审核案件，输出整改清单或通过
  • 企业IPR：查看本企业预审进度

业务规则

  • 未通过准入预检的案件不可提交预审
  • 非正常筛查问题数超过 5 项自动驳回
  • 整改清单需在 7 日内反馈，超时自动置为已驳回
  • 同一申请人同一技术领域 30 日内不可重复提交
阶段 1 · 完整需求文档（requirement-input.md · 4548 字符）

PM 需求详版 — 专利预审智能合规预审管家

本文档由 AI 基于 requirement-scenario-brief.md 与需求模型扩展生成，作为 Demora Phase 1 的 PM 详细需求归档。

1. 业务背景

1.1 行业现状

  • 国家知识产权局在全国布局 77 家知识产权保护中心，覆盖广州等产业园区重点产业
  • 通过预审通道的发明专利授权周期可由常规 22 个月压缩至 3 个月以内
  • 国知局近年严控预审准入，对非正常、低质量申请执行严格筛查
  • 企业与代理机构在提交预审前缺乏统一的智能预检工具，导致大量案件被驳回或反复整改

1.2 痛点

  • 预审准入复杂：主体备案 / 技术领域匹配 / 同日重复校验等规则手工核对，效率低
  • 非正常筛查专业门槛高：研发证明 / 技术逻辑 / 权利要求 / 附图 / 发明人 5 维度判断需专利代理经验
  • 整改时限易失控：整改清单 7 日内反馈，超时自动驳回，案件流程难跟踪
  • 数据无统一台账：代理机构多客户多案件并行，缺乏全流程可视化看板

1.3 价值主张

构建一站式专利预审智能合规预审管家，提供「准入预检引擎 + 非正常筛查 + 整改闭环 + 全流程台账」四合一能力，让代理师与预审员协同工作，企业 IPR 实时跟踪进度，最终将预审通过率从行业平均 60% 提升至 85% 以上。

2. 用户角色

2.1 代理师（agent）

  • 职责：提交预审案件，跟进预审员反馈的整改清单，按时完成整改回填
  • 权限范围：全部预审案件的 create / read / update / delete（all scope）
  • 页面可见性：P01 案件列表、P02 案件详情、P03 案件提交表单

2.2 预审员（precheck-reviewer）

  • 职责：审核代理师提交的预审案件，输出整改清单或通过 / 驳回决定
  • 权限范围：全部预审案件的 read / update（all scope），不可创建 / 删除
  • 页面可见性：P01 案件列表、P02 案件详情

2.3 企业 IPR（ipr）

  • 职责：查看本企业案件的预审进度，了解整改反馈
  • 权限范围：仅本人所属企业案件 read（own scope）
  • 页面可见性：P01 案件列表、P02 案件详情

3. 核心功能

3.1 预审案件全流程台账（P01）

  • 分页展示代理机构全部预审案件
  • 支持按案件编号、申请人、技术领域、预审员、状态多维度搜索
  • 支持「新增案件」「批量预检」操作
  • 企业 IPR 仅查看本企业案件，代理师与预审员可见全部

3.2 案件详情与流程闭环（P02）

  • 展示案件基础信息（案件编号 / 申请人 / 技术领域 / 代理机构 / 状态）
  • 展示预审员姓名与预审开始时间
  • 展示非正常筛查问题清单与整改建议
  • 支持预审员「开始预审」「通过」「驳回」三步状态流转

3.3 案件提交表单（P03）

  • 表单字段：案件编号、申请人、技术领域、代理机构（均为必填）
  • 支持「准入预检」预检引擎调用（含 30 日重复提交校验）
  • 支持「提交」「取消」操作

3.4 准入预检引擎

  • 主体备案校验：申请人是否已完成预审主体备案
  • 技术领域校验：申请技术领域是否在保护中心支持范围
  • 同日重复校验：同一申请人同一技术领域 30 日内不可重复提交

3.5 非正常专利全维度筛查

  • 研发证明合理性
  • 技术逻辑自洽性
  • 权利要求清晰度
  • 附图与说明一致性
  • 发明人真实性

  • 入口：列表页点击「新增案件」

  • L3 元件：提交按钮、准入预检按钮、取消按钮
  • 业务规则：提交前必须通过准入预检；30 日内重复提交时提示错误

5. 业务规则

5.1 状态机

已提交 (submitted) 
   ↓ 预审员点击「开始预审」
预审中 (checking)
   ↓ 预审员点击「通过」
预审通过 (passed)
   ↓ 预审员点击「驳回」（弹出整改清单输入弹窗）
预审驳回 (rejected)
   ↓ 代理师完成整改回填
已整改 (rectified) → 可再次进入预审中

5.2 权限矩阵

代理师 ✓ ✓ ✓ ✓ all
预审员 ✗ ✓ ✓ ✗ all
企业 IPR ✗ ✓ ✗ ✗ own

5.3 业务约束

  • 案件编号、申请人、技术领域、代理机构为必填
  • 技术领域枚举：新一代信息技术 / 高端装备制造 / 新材料 / 生物医药 / 新能源 / 节能环保
  • 同一申请人同一技术领域 30 日内不可重复提交
  • 未通过准入预检的案件不可提交预审
  • 非正常筛查问题数超过 5 项自动驳回
  • 整改清单需在 7 日内反馈，超时自动置为已驳回

6. 验收标准

6.1 结构契约（check-structure.mjs 10/10）

  • HTML 含 data-annotation-root 根元素
  • 三个 [data-page-id] 页面 section（P01/P02/P03）
  • 顶部工具栏含 [data-annotation-toggle] 标注开关
  • 每个页面至少 1 个 data-zone-id L2 区域 + 1 个 data-element-id L3 元件
  • 每个页面至少 1 个 .l2-marker 序号 + 1 个 .l3-dot 指示器
  • &lt;script&gt; 中定义 window.__ANNOTATION_DATA__ 对象，含 P01/P02/P03 完整 L1/L2/L3 数据

6.2 路由契约（D2 PASS）

  • 默认路由指向 P01（#/precheck-cases）
  • 监听 hashchange 事件
  • 页面 section 切换通过 hidden 属性控制
  • 导航点击后 URL hash 变化且页面内容同步切换

6.3 弹窗契约（D3 PASS）

  • P02 驳回弹窗有可点击的关闭按钮（×）
  • 点击遮罩层关闭弹窗
  • ESC 键关闭弹窗

6.4 标注契约（D4/D5 PASS）

  • L2 marker 闪烁动画正常（5 次 transform 切换）
  • L3 dot 可点击（pointer-events 不被覆盖）
  • .l2-marker / .l3-dot / .anno-zone 等保留类名不在 style.css 重复定义

6.5 业务功能（D6 PASS）

  • P01 搜索：输入案件编号 / 申请人 / 选择技术领域 / 选择状态后点击搜索，表格刷新
  • P01 新增：点击「新增案件」跳转 P03
  • P01 批量预检：选中行后点击，提示「批量预检任务已启动」
  • P02 流程：状态为已提交时显示「开始预审」；状态为预审中时显示「通过」「驳回」；点击「驳回」弹出整改清单输入弹窗
  • P03 准入预检：点击后显示「准入预检通过」或「30 日内重复提交，不允许」
  • P03 提交：校验通过后跳转 P01
  • 按钮响应率 ≥ 80%

  • Mock 数据 ≥ 10 条 precheck-case，覆盖 6 种技术领域 + 5 种状态
