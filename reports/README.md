# GitPulse 报告门户（reports/）部署与使用说明

本目录是 GitPulse 全部期次评估报告的**可部署静态站点**：`index.html`（本目录根）为总入口，可进入每个项目的引导页，再进入该项目每一期的可视化报告。

**导航（SPEC-016 v2/v3）**：项目引导页顶部含面包屑「首页 / 项目名」，一键回退总入口；各期仪表盘右下角有「← 返回项目引导」固定浮标（v3，由 portal 注入/重跑时自动补齐，报告数据不受影响）。

**独立运营项目**：`pat-crosssem` 独立运营（2026-11-02 用户口径）——**不出现在总入口**；其引导页 `pat-crosssem/index.html` 照常生成（含该项目全部期次），顶部无主页链接、可**单独打包部署**。打包主站点时可将 `reports/pat-crosssem/` 整目录排除。

## 目录结构

```
reports/
├── index.html                  ← 总入口（部署后站点首页）：项目卡片 → 项目引导页（不含独立运营项目）
├── <项目名>/index.html          ← 项目引导页：该项目每一期 pulse 报告列表（顶部面包屑回主页）
├── <项目名>/<YYYY-MM-DD-HHmmss>/ ← 一期运行：index.html（自包含仪表盘）+ summary.md + <仓库>/report.md（分册）
├── pat-crosssem/               ← 独立运营项目（不在总入口呈现；可整目录单独打包）
├── _non-pulse/                 ← 演练样例归档（不属门户条目，可随包或排除）
└── _scripts/                   ← 生成与采集工具（部署无需包含）
```

## 部署（作为 Web 服务）

1. **打包**：将 `reports/` 整体打包（如 `reports.zip`）。门户页为纯静态、零外部依赖、全相对链接——`_scripts/` 与 `_non-pulse/` 与门户无引用关系，可按需排除以减小包体。
2. **上传**：解压至生产服务器任意静态文件服务目录（Nginx `root` / Apache `DocumentRoot` / IIS 站点 / 对象存储静态托管均可），无需任何服务端运行时。
3. **访问**：浏览器打开 `http://<服务器>/<路径>/index.html` 即总入口。单期报告均为单文件自包含（echarts 已内联），也可直接离线发送。

## 报告更新后刷新门户

每执行一期 pulse 后重跑：

```
python -I reports/_scripts/pulse_tool.py portal
```

生成器只读各期归档、幂等重写门户页（总入口 + 各项目 index.html），不修改任何已归档期文件；内置自检：死链与外链为 0 时退出码 0。

## ⚠ 敏感度提示（RUNBOOK §5.4.2 口径）

本站聚合全部监测汇总数据（项目名称、成员姓名与评分、风险结论、仓库地址等）。**公网发布前请自行评估敏感度**；建议内网部署或点对点分发。门户页脚随页提示同口径。
