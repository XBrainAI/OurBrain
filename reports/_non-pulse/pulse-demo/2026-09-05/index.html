研发项目进度与风险监测报告

本期怎么看（一句话）

进度与交付 —— 我们在按计划走吗？（对应五维中的「进度」）

需求 / 里程碑进度条

每行一条需求或里程碑：圆点 = 交付截止日在计划区间里的位置，深色竖线 = 今天；圆点越靠近「今天」越紧急，越靠右表示已超出本次统计窗口。

提交节奏（逐日）

窗口期每天提交了多少次：长期 0 的日子 = 停滞；截止日（图中竖线）前突然变高 = 突击。tooltip 里能看到与前一日的比较。

增量提交分析（本期提交做了什么）

左 = 本期提交按类型分布（新功能 / 修缺陷 / 杂项）；右 = 有效提交占比（合并提交不计入工作量）；下方列出碎片化小提交，供研判是否存在"刷提交量"式工作。

风险全景 —— 哪里可能出问题？（对应五维：进度 / 人员 / 质量 / 集成 / 规范）

异常信号墙（高 / 严重）

需要管理层立刻知道的事：色块颜色 = 等级（红比橙急），「已连续 N 期提醒」= 这个问题连续多期都没解决。

风险总览

风险分 0~100，越高越危险：0~25 低 / 25~50 中 / 50~75 高 / 75~100 严重；箭头 = 与上期环比（↑ 恶化 / ↓ 好转）。

五个维度的风险形状

进度=做得跟计划一样快吗 · 人员=活是否压在少数人身上 · 质量=欠的技术债多吗 · 集成=代码合并顺畅吗 · 规范=记录可追溯吗。越外圈 / 越红 = 该维度越危险。

五维得分热力（仓库 × 维度）

每格 = 某仓库某维度的危险程度（0 健康 → 100 危险），用于快速定位"哪个项目、哪个方面"最需要介入。

跨期趋势

每期健康分按运行日期走势：持续上升 = 问题在累积，关注拐点与分层。仅一期时显示基线说明。

团队与人效 —— 活是谁干的？投入健康吗？（对应五维中的「人员」，并关联「质量 / 集成 / 规范」）

谁在哪个分支干活（孤岛 = 单一颜色）

每行 = 项目里的一个人，彩条 = 他在各个分支上的有效提交数：只有一种颜色说明他只在一个分支干活（知识孤岛——他请假就没人接手）；条明显比别人短 = 投入骤降。

提交都花在哪了（核心 vs 其他）

每行 = 一个代码目录的变更量：蓝色 = 计划内的核心模块，灰色 = 其他；灰色很长、蓝色很短 = 看起来很忙但计划的事没做。

分支合并状况

两张小图分开看：上 = 已完成还没合并回去的工作量；下 = 落后主干（未同步）的提交数——两边的量级差异本身也是信号。

质量信号

四项体检指标对照预警线：红色 = 超标，需要安排处理。

仓库全景（自开始至今） —— 立项以来这个仓库经历了什么？（对应 §1.15 全生命周期统计）

全生命周期指标

仓库从第一次提交到今天的整体规模：看总量与人数，判断项目体量与团队规模。

逐月提交趋势（自开始至今）

仓库诞生以来每个月的提交量：高峰 = 集中开发期，低谷 = 停滞期；对照里程碑看节奏是否合理。

全期贡献者 Top 5

仓库诞生以来提交数前 5 的成员：看关键人依赖与知识分布。
